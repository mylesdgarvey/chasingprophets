# Stack Architecture (Alpha)

Date: 2025-11-06
Status: Updated for contract-based scaffold system

## Frontend
- React 18 + TypeScript (Vite)
- Plotly.js for charts
- Monaco Editor for code editing (Python/JavaScript scaffold scripts)
- KaTeX for LaTeX formula rendering
- Auth via AWS Cognito User Pools (hosted UI optional)
- Deployed with AWS Amplify Hosting
- **Client-side inference**: Executes JavaScript inference scripts in browser for performance visualization

## Backend (initial alpha)
- API: API Gateway (REST) → Lambda (Python 3.11) [planned]
- Daily jobs: EventBridge → Lambda for data refresh + prophet metrics
- Training: Lambda (for simple models) or ECS Fargate task per job (for complex models) [planned]
- **Remote inference**: Lambda executes Python inference scripts from S3
- Until full backend is ready, client uses pre-seeded DynamoDB and S3 data

## 2. Data Layer

- **Amazon DynamoDB**: Fully managed NoSQL database for all core metadata. All tables provisioned with on-demand capacity.
  - **Assets**: Stores metadata about financial assets (e.g., DJIA, SPX).
  - **AssetPrices**: Stores OHLCV time-series data (deprecated for raw price storage; now only used for metadata).
  - **Datasets**: Metadata defining a collection of data for an asset; points to S3 CSV paths.
  - **DataSlices**: Defines a specific subset of a Dataset with analyzed schema:
    - **Simple slices**: Single contiguous time period
    - **Compound slices**: Union of multiple simple slices (e.g., train+validation)
    - Date range (startDate, endDate - computed for compound slices)
    - Available columns (e.g., ["date", "open", "high", "low", "close", "volume"])
    - Column types (e.g., {close: "numerical", date: "datetime"})
    - Column ranges (e.g., {close: {min: 100.5, max: 450.2}})
  - **ModelScaffolds**: Contract-based blueprint for predictive models:
    - **Type**: `context-free` (generic variables like x1, y1) or `context-dependent` (specific variable names like `close`, `volume`)
    - **Learning algorithm**: Specific training method (e.g., `ordinary_least_squares`, `maximum_likelihood_estimation`)
    - **Model categories**: Major category (e.g., `econometrics`) and specific model (e.g., `simple_linear_regression`)
    - **Formula (LaTeX)**: Optional mathematical representation of the model for display
    - Input/output contracts (field names, types, value ranges)
    - Three script paths in S3: training.py, inference.py (remote), inference.js (local)
    - Inference mode (local, remote, or hybrid)
  - **ModelFits**: The result of training a ModelScaffold on a DataSlice:
    - Stores model parameters in S3 (e.g., regression coefficients)
    - Copies scaffold's inference script paths for execution
    - Training status (unfit, fitting, fit, failed)
  - **Prophets**: An actionable predictive agent using ModelFit(s):
    - **Ensemble support**: Each prophet references one or more ModelFit IDs (`modelFitIds: string[]`)
    - **Ensemble methods**: `single` (one model), `average`, `weighted_average`
    - **Ensemble weights**: Optional array of weights for weighted ensemble
    - **Output transformation**: S3 path to JavaScript script that post-processes model outputs (e.g., convert returns → prices)
    - **Target property**: The specific entity attribute being predicted (e.g., `close`, `volume`)
    - **Forecast method**: How predictions are extended (e.g., `direct`, `recursive`)
    - **Status**: `pending_training`, `active`, `inactive`, `failed`
    - **Performance metrics**: Stored inline (RMSE, MAPE, directionalAccuracy, R²) updated daily
    - Executes remote inference daily via scheduler
    - Supports local inference for client-side visualization
  - **Forecasts**: Time-bound predictions generated by a Prophet (daily scheduler output):
    - **Fixed horizons**: System supports 8 standard forecast windows (5, 20, 60, 120, 240, 480, 1200, 2400 days)
    - Each forecast stores: prophetId, assetId, horizon, startDate, endDate, predictions array, performance metrics
    - **Per-window performance**: Each forecast computes its own RMSE/MAPE/directionalAccuracy for that specific window
  - **Performance**: Stores *daily* raw performance data (predicted, actual, error) - NOT persisted long-term.
  - **ProphetPerformanceSummary**: Stores aggregated rolling-window performance metrics:
    - Windows: 20d, 40d, 60d, 120d, 240d, 480d, 1080d, 1200d
    - Metrics: MAPE, RMSE, directional accuracy, percentile errors
    - Used for leaderboard ranking
  - **Users, Notifications**: Standard application tables.

- **Amazon S3**: Single bucket per env: chasingprophets-models-{region}
  - **Model artifacts**: `models/{modelFitId}/parameters.json` (trained model parameters)
  - **Raw price data**: `data/assets/{TICKER}/ohlcv_full.csv` (DJIA, SPX, etc.)
  - **Data slices**: `slices/{dataSliceId}.csv` (optional; derived from asset CSVs)
  - **Scaffold scripts**: `scripts/scaffolds/{scaffoldId}/`
    - `train.py` - Training script (Python)
    - `inference.py` - Remote inference script (Python, runs on Lambda)
    - `inference.js` - Local inference script (JavaScript, runs in browser)

## Security & IAM

## Eventing & Inference Architecture

### Daily Scheduler (Server-side Remote Inference)
- **Time**: 06:00 ET daily
- **EventBridge Rule** → **Lambda: chp-daily-predictions**
  - For each active prophet (status = 'active'):
    - Fetch latest OHLCV data from S3
    - For each modelFit in prophet.modelFitIds:
      - Load model parameters from S3
      - Download and execute remote inference script (Python) from S3
      - Generate raw model output
    - **Ensemble combination**: Combine multiple model outputs using prophet.ensembleMethod
    - **Output transformation**: Execute output_transform script from S3 to convert model outputs → final predictions
    - Generate predictions for standard forecast horizons (5, 20, 60, 120, 240, 480, 1200, 2400 days)
    - Store forecasts in Forecasts table (one record per horizon)
- **EventBridge Rule** → **Lambda: chp-daily-performance** (runs after predictions)
  - For each active prophet:
    - For each forecast horizon:
      - Fetch forecast predictions
      - Fetch actual values from AssetPrices
      - Compute error metrics (RMSE, MAPE, directional accuracy)
      - Update per-window performance in Forecast record
    - Aggregate metrics and update Prophet.performance (overall metrics)
    - Update rolling aggregates in ProphetPerformanceSummary
    - Discard individual daily performance data (only keep aggregates)

### Client-side Local Inference (On-demand Visualization)
- **Trigger**: User views `/prophets/:prophetId` or `/mgmt/models/fits/:modelFitId`
- **React Application**:
  - Fetches prophet/model fit metadata from DynamoDB
  - For each modelFit in prophet.modelFitIds:
    - Fetches model parameters from S3 (via pre-signed URL)
    - Fetches local inference script (JavaScript) from S3
  - Fetches historical OHLCV data from S3 (configurable: 60, 120, 240, 1200 days)
  - Fetches output_transform script from S3
  - **Executes inference pipeline in browser**:
    - For each day in historical data:
      - Run each model's inference script → get raw outputs
      - Combine outputs using prophet.ensembleMethod
      - Apply output_transform script → get final prediction
    - For each forecast horizon (5, 20, 60, 120, 240, 480, 1200, 2400 days):
      - Generate rolling-window forecasts
      - Compare predictions to actuals
      - Compute performance metrics (RMSE, MAPE, directional accuracy)
  - **Renders multi-window visualizations**:
    - Grid of 8 charts (one per horizon)
    - Each chart: predicted vs actual price path, error bands, metrics display
    - Aggregate leaderboard metrics across windows
- **Fallback for remote-only scaffolds** (when `inferenceMode === 'remote'`):
  - React calls API: `GET /api/prophets/:prophetId/historical-inference?days=1200&horizons=5,20,60,120,240,480,1200,2400`
  - Lambda executes remote inference script and returns pre-computed predictions per window
  - React renders charts from API response

### Contract Validation Flow
1. **Admin creates Data Slice**:
   - System reads CSV from S3
   - Analyzes schema: extracts column names, types, and value ranges
   - Stores in DataSlice record (availableColumns, columnTypes, columnRanges)

2. **Admin creates Model Fit**:
   - Selects Asset, Scaffold, and Data Slice
   - System validates scaffold's input contract against slice schema:
     - Check all required input fields exist in slice columns
     - Check field types match
     - Check value ranges are within allowed bounds
   - If validation passes: allow fit creation
   - If validation fails: show error with details (missing fields, type mismatches, range violations)
